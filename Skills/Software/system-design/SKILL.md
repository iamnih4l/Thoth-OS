# System Design

## Purpose
Guide the process of designing large-scale distributed systems from requirements gathering through component design, data modeling, and scalability planning.

## When to Activate
- Designing new systems or services from scratch
- Preparing for system design interviews
- Evaluating scalability of existing architectures
- Making build vs buy decisions

## When NOT to Activate
- Simple CRUD applications with no scale concerns
- Pure frontend tasks with no backend architecture needs

## Workflow
1. **Understand** - Analyze requirements and constraints
2. **Plan** - Design the approach with appropriate patterns
3. **Implement** - Build using best practices
4. **Validate** - Test against requirements and edge cases
5. **Document** - Capture decisions and usage instructions
6. **Review** - Self-review for quality and completeness

## Checklist
- [ ] Requirements clearly understood
- [ ] Approach designed before implementation
- [ ] Best practices applied
- [ ] Edge cases handled
- [ ] Tests written for critical paths
- [ ] Documentation updated
- [ ] Code reviewed for quality
