# Design Patterns

## Purpose
Recognize common design problems and apply appropriate patterns (creational, structural, behavioral) for clean, extensible solutions.

## When to Activate
- Encountering a recurring design problem
- Refactoring code to improve structure
- Building extensible plugin or component systems

## When NOT to Activate
- Simple scripts that don't benefit from abstraction
- Premature abstraction before patterns emerge naturally

## Workflow
1. **Understand** - Analyze requirements and constraints
2. **Plan** - Design the approach with appropriate patterns
3. **Implement** - Build using best practices
4. **Validate** - Test against requirements and edge cases
5. **Document** - Capture decisions and usage instructions
6. **Review** - Self-review for quality and completeness

## Checklist
- [ ] Requirements clearly understood
- [ ] Approach designed before implementation
- [ ] Best practices applied
- [ ] Edge cases handled
- [ ] Tests written for critical paths
- [ ] Documentation updated
- [ ] Code reviewed for quality
