# PRD Writing

## Purpose
Create clear, actionable PRDs that align engineering, design, and business stakeholders.

## When to Activate
- New feature definition
- Feature refinement
- Sprint planning preparation

## When NOT to Activate
- Bug fixes with clear scope
- Technical refactoring tasks

## Workflow
1. **Understand** - Analyze requirements and constraints
2. **Plan** - Design the approach
3. **Implement** - Build with best practices
4. **Validate** - Test and verify
5. **Document** - Capture decisions and usage
6. **Review** - Quality assurance

## Checklist
- [ ] Requirements understood
- [ ] Approach designed
- [ ] Best practices applied
- [ ] Edge cases handled
- [ ] Tests or validation complete
- [ ] Documentation updated

## Input Format
```yaml
task: 'Task description'
context: 'Project context'
```
